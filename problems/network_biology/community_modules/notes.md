# 实现笔记

`modularity` 可以逐社区计算：数内部边数、累加度之和，再套用公式。只有不同的非自环边才计数，所以先构建邻居集合。计算之前先检查 communities 是否构成划分。

贪心算法需要维护 `members`、`degree` 和 `links`（社区 → 邻居社区 → 边数）。每一轮对每个相连的 `(a, b)`（`a < b`）计算增益，选取 `(−round(gain, 12), a, b)` 的最小值，最大增益不大于零时停止。把 `b` 并入 `a` 时累加度和成员列表，并把 `b` 的每个邻居 `c` 的边数转到 `a` 上。合并后的社区沿用 id `a`，因为 `a < b`，它仍是最小成员。

常见错误：

- 忘记对度项平方，或把每条内部边数了两次。
- 在任一函数中忽略 `resolution`。
- 增益恰好为零时仍然合并（4 节点环应以两对结束，而不是合成一组）。
- 合并彼此没有边的社区，或丢掉孤立节点。
- 把并列交给字典顺序，而不是按所述的名称规则。

## 复杂度

每一轮扫描所有相连的社区对，为 O(M)（M 条边），至多 N − 1 轮，所以参考实现为 O(N·M)。更快的算法（如 Louvain，或带堆的 Clauset-Newman-Moore）存在，但不要求。

## 为什么结果会变化

贪心模块度是启发式算法。不同的并列规则、合并顺序和分辨率参数会改变划分，模块度本身也无法分辨大网络里很小的模块。测试中预设模块的图有明显的最优解，所以可以安全地使用精确期望；不要指望贪心结果在一般图上是最优的。

## 科学上的谨慎

社区是关于图的结构性陈述。把它称为“模块”是一个需要生物学支持的假设，例如共同注释的富集、独立数据中的重复和实验。不要把检测到的社区当作已验证的通路报告。
