# 实现笔记

输出标记的是**目标**角色，不是预测位置角色。user token 后可以是需要监督的 assistant token；assistant token 后也可以是不监督的 user token。用多轮案例同时检查这两个方向，不要先错位掩码，再在 loss 中重复错位。

只比较相邻位置的会话编号。把所有位置与第零列比较，会错误丢掉后续 packed 会话。编号数值、batch 排序和轮次数量都不影响规则。新会话首 token 没有同会话前驱，即使角色是 assistant 也排除。左截断后的第一个保留 token 同理；右截断既不抹掉此前的目标，也不补造 EOS。

有效性是独立输入：目标和紧邻前驱都必须是真实 token，padding 下的元数据不能参与决定。这也能区分相同编号的 EOS 与 PAD。调用方将 assistant EOS 标为角色 2，它仍是合法目标；算法不在第一轮回答或第一个 EOS 后停止。角色头和 BOS 已在上游标为 0。

时间复杂度 O(BT)，输出空间 O(BT)。B/T 为空时没有特殊 token；参考解仅写入新建的布尔结果，不修改输入。整数元数据不要求梯度，梯度测试验证的是掩码接入提供的损失后的效果，而非对角色编号求导。

## 来源范围

TRL SFT 文档提供 assistant-only 监督与 next-token 标签对齐的依据，packing 文档说明了不同策略和截断。数值角色、显式会话编号、EOS 归属与前驱规则是本题独立且受限的教学接口；不能据此宣称复现 TRL 预处理，也不能省略真实模型的 attention 隔离。

## 实验与验收

两行固定数据共 24 个 token 位置、11 个合法目标。每个预测位置独立拥有四个 float64 logits，全部从零开始；SGD 学习率为 4，执行恰好 80 次更新，不采样、不下载数据。标准种子为 42，但本实验没有随机调用。参考与提交代码使用相同训练循环。

独立手工标签决定评估 NLL 和哪些参数应保持不变。初始 NLL 为 ln(4)；正确实现应使最终目标 NLL 小于 .08、准确率等于 1，且每个被排除的 logit 变化严格为零。阈值在确定性参考结果之上留有余量，同时要求有实际优化。这不是留出集或共享语言模型实验，展示的是训练作用位置；所有曲线均来自真实更新。

四个 mutant 分别错误使用预测角色、遗漏会话边界、遗漏 padding、监督第零列。每个只改变一条规则，由直接断言捕获。在错误掩码上学到低 loss 不算通过：测试还检查独立目标损失、掩码差异和被排除参数的变化。

2026-10-17 校准：macOS arm64、Python 3.14.2、原生 Torch 2.14.1，最终目标 NLL 为 `0.02795611111943972`、准确率 `1.0`、排除 logits 变化 `0.0`。三轮原生参考/变异验证共 120 个测试用例通过，四个 mutant 全部被捕获。相同导出测试包在 Pyodide 0.29.4 / NumPy 2.2.5 中通过 8 个参考测试、四个断言捕获的 mutant 与 8 个学员测试，包含同样的 80 次训练更新。这是对应环境的正确性记录，不是通用延迟保证。
