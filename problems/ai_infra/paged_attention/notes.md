# PagedAttention 题解

先算所需页数 `(L + S - 1) // S`，取块表的有效前缀，再用这些块号索引物理 KV cache。索引得到 `(ceil(L/S),S,H,D)`，合并前两维后截取前 $L$ 个 token，便得到逻辑序列。不能排序块号，也不能直接取物理 cache 的前若干页。

对请求 $b$，逐 token、逐 head 计算 query 与 key 点积，除以 $\sqrt D$。将 token 维放在 softmax 的归一化轴上，得到权重后乘对应 value，再对 token 求和。

每个块中的权重使用同一个全上下文分母。若独立计算每页 softmax 再相加，会给每页错误的总权重。参考实现先收集逻辑序列以明确这一数学约定；实际 GPU kernel 可以分块读取并合并归一化统计量。

最后一页常未填满，截断必须先于有限值验证和 attention。有效长度以外的 NaN 或大数既不能进入分母，也不能影响输出。未使用的块表项也不必是有效物理页号。

高级索引和 reshape 保留梯度。当两个请求读取同一物理页时，自动微分会将贡献累加到原始 cache。测试使用零 query 和零 key 令权重均匀：一个 token 被长度 3 与长度 4 的两个请求共同读取时，每个 value 分量的梯度为 $1/3+1/4$。未读槽位的梯度应为零。

解码回放还验证物理页的布局不会改变结果。内存槽计数来自实际引用的不同物理页，而不是所有逻辑页数量；共享前缀页只能计一次。这里不测运行速度。
