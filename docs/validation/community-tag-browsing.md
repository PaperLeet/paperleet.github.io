# Bounded community tag discovery and selection

The public tag browser and the shared publication/editing picker now show eight matching options initially. Explicit expansion reveals up to eight more in maintained taxonomy order. A persistent compact control can return to the first batch before reaching the end. Counts distinguish shown options from the complete matching inventory; local search still covers all 200 supported tags, including bilingual names, identifiers and full descriptions. Search, expansion and compaction never apply a feed filter, change a tag selection, refetch taxonomy or publish a post. The options use the page or existing workspace scroll area rather than a second fixed-height scrollbar.

The shared local search handles Enter without submitting its containing publication form or bubbling into parent shortcuts. Composition Enter remains available for native IME completion; committed queries are bounded to 100 Unicode code points, normalize public matching with NFKC and treat punctuation literally. Escape clears a nonempty query, while a second Escape in the discovery browser closes the disclosure and returns focus to its summary. Modifier, repetition and composition guards protect the browser's native behavior. Changing the normalized query resets the display window; locale changes and opening/closing the browser retain the local finder. Existing applied-tag summaries and selected chips stay available independently of the matching window.

An explicit reveal focuses the first new native tag control. At the five-selection cap the picker instead focuses the first new labelled option group, so its description remains readable without enabling an addition. Compaction focuses its surviving control. The existing workspace-intent lease yields to newer input/focus, wheel/scroll intent, route changes, owner retirement, disabled state and hidden/closed disclosures. Search recovery and removal of an existing paused association repair focus before a control disappears. The five-tag limit, legacy-service recovery, historical-tag edit rules, publication nonce/version checks and captured retry payloads are unchanged.

Validation includes a 200-tag React/JSDOM StrictMode inventory, complete explicit traversal, bilingual/identifier/description and full-width search, zero-result recovery, code-point/composition/Enter/Escape contracts, no implicit form submission, early compaction and first-new-control focus, disabled/five-tag and paused/unknown states, locale and owner retirement, newer focus/wheel/route/closed-disclosure cancellation, and unchanged private editor/body, caret, scroll and session-draft state. The existing actual Community composer suite also checks Enter on a valid publication form. A separate public JudgeHandler/SQLite flow serves the same 200-term inventory through the real taxonomy endpoint, then verifies that all local UI operations preserve the entire database schema and row contents. Existing tag-scoped publication and editing regressions remain required.

Four frontend build variants retain the existing startup byte budgets, deferred community graph, catalog math and static-route checks. No schema, API, catalog, dependency, algorithm or judge/runtime changes are made. Retained numerical evidence stays bound to its original execution commits.

Limits: controlled DOM events and viewport rectangles verify the code paths, not physical browser layout, native IME/select/focus/clipboard or live identity providers. This wave does not deploy or dispatch CI.
