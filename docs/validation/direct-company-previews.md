# Direct company evidence in the practice workspace

Company evidence tags inside a valid exercise workspace now open that company's existing source preview in place. The native buttons retain the source counts and descriptive contributor labels, identify the controlled region and expose its expanded state. Selecting another company replaces the preview cohort, and selecting the open company closes it. Ranking and other standalone source lists keep their ordinary full-source links.

The preview has a selected-company heading, publication-cohort counts and a 44-pixel top close control as well as the existing footer and return-to-code action. An explicit tag selection focuses the heading once, before any asynchronous source response. The existing workspace-intent lease yields to newer code focus/input, route changes and owner retirement. Source responses never focus the preview. Closing from the panel returns to the exact company tag; if a publication-period refresh removed that tag or its disclosure was collapsed, focus returns to the surviving generic preview toggle. The initial three-plus-more company presentation, current period, native company selector and locale continuity remain available.

The interaction uses the same public summary and bounded three-report source API. No source read happens merely because tags become visible or the extra-company disclosure opens. Switching companies aborts the old source request. The selected module, company and publication period are validated by the existing protocol; stale route/owner responses remain rejected. Full experiences still open in a separate tab from the practice preview. Nothing serializes private code or changes a practice draft, account setting or public post.

Validation extends the actual React/JSDOM practice-evidence suite with direct tag selection, one-time heading focus, cohort switches and stale-response rejection, newer code focus, company disclosure and exact-origin/fallback closing, locale and account retirement, return-to-code continuity and both legacy hash and production path routing. The existing ranking and concept-journey suites still require native full-source links outside the exercise preview. The disposable JudgeHandler/InterviewService/SQLite flow now opens Google directly from its company tag, reads only that company, changes publication periods and verifies the expected public reports without UI mutations. Existing source-body reading, anonymous affiliation, strict protocol, retry/timeout and editor preservation regressions remain required.

Four frontend build variants retain the existing startup budgets, deferred feature graph, catalog math and static routes. No API, schema, catalog, dependency, algorithm or judge/runtime inputs change. Retained numerical evidence is read and hashed at its original execution commits; no numerical probes are executed for this UI change.

Limits: controlled DOM events and routing verify these code paths, not physical browser layout, native select/IME/clipboard behavior or live identity providers. This wave does not deploy or dispatch CI.
