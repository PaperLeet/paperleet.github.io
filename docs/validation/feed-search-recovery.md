# Search recovery and search-draft isolation

Community discussions, community solutions and interview reports distinguish a successful zero-match search from an empty community, a request failure and an access gate. The shared panel uses a readable heading, a quiet search icon and two wrapping 44-pixel actions. Saved searches name the saved scope explicitly. It does not echo search text into a live region or render search text as markup.

Clear search removes only the applied keywords and resets the page to one. Community topic, post type, board, tag, saved/following membership, order and publication period remain selected. Interview company, role, stage, outcome, period, location/month, concept and saved scope remain selected. Adjust filters synchronously focuses and reveals the existing filter toolbar without changing a URL, request or an unsubmitted input. Late results never repeat that focus or scroll action.

Unsubmitted community search text is retired when the topic, post type or board changes. Adjusting publication period, sorting, tags, membership filters or pagination within that context keeps the unsubmitted search draft and its explicit not-applied feedback. Both community and interview search inputs are keyed to the current actor and a separate pending-account identity. Switching accounts, signing out or confirming an account cannot carry an outgoing search draft into the next actor. Locale changes retain the same input, text and selection. This state is transient and adds no persistent storage, API, schema or dependencies.

Actual React/JSDOM feed tests cover saved and public empty matches, local-only filter focus, apply-versus-draft behavior, scope-preserving recovery through a held request, actor and hydration isolation, board changes, translated labels, request/access failures, and unchanged practice code, composer, caret, scroll and storage. The existing disposable HTTP/SQLite interview flow additionally proves zero matches and clear-to-three public reports under the exact company/role/location/month scope while preserving the complete database. The tests do not establish physical browser geometry or native input/focus behavior.
