# Discussion reading after practice

A same-tab practice entry from a discussion captures applied reply query/order/author scope, mounted batch size, bounded versioned full-reply expansions and the exact public practice control/viewport offset. The owner-scoped session record has a strict versioned schema, one active journey, a six-hour lifetime and bounded input size. It does not read or serialize the code editor or reply drafts. Search terms remain local; links carry only the existing canonical source post ID.

Maintained unique exercise numbers such as `#22` now use the existing literal practice-mention transform in public reply Markdown. Retired or ambiguous numbers, URL/identifier fragments, code, math and author-supplied links are excluded. The original source is unchanged.

The workspace confirms the current route using a real catalog entry. Previously confirmed list origins continue observing back navigation while catalog metadata is pending; a bounded transient route queue bridges the optional helper load, accepts only the unchanged captured record and current owner, and retires unrelated navigation; new discussion confirmation still requires a real entry. The helper loads after an actual workspace visit rather than in the initial library. A fresh workspace can rehydrate the journey after reload; late effects cannot overwrite a returned or unrelated route. Canonical navigation stays usable if optional recovery loading fails, and the discussion offers explicit recovery when a return cannot be confirmed automatically.

On return, reply state and version-matching expansions commit first. The final notice commits before position is measured. The original region and repeated-link instance distinguish a reply, article reference, mentioned exercise, topic control and experience practice/next action even when URLs coincide. Collapsed practice groups reveal the original exercise without starting it. Live header/viewport visibility is respected.

A linked reply takes priority over personal recovery. Newer focus or interaction prevents automatic positioning; hidden pages wait. Updated or removed content has an explicit fallback, including deliberate original-reply reveal when available. Expired recovery keeps the current reading view. Dismissing a notice retains a fully visible reading anchor and avoids selecting disabled controls. Account changes retire the prior owner's view. Browsing does not run, submit, publish, flush practice or write account data.

`web/scripts/check-discussion-practice-return.mjs` covers strict storage/model transitions, actual App/Community/workspace traversal, helper deferral and fresh-App reload, committed-notice geometry, duplicate-region/link selection, hidden/delayed recovery, explicit shared replies, changed/deleted source, expiry and private editor/draft/caret/scroll isolation. Existing source-post, reading-return, reply, interview-practice and mention tests remain in the full gate. Verification uses source and controlled React/JSDOM plus separate disposable HTTP/SQLite contracts; it does not claim browser rendering, physical IME, native focus trapping, OS clipboard or device validation.
