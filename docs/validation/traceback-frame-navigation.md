# Traceback frame navigation

Expanded diagnostics now let readers select each explicitly matched implementation frame, including callers, internal helpers and repeated calls. The existing summary action still selects the last valid implementation frame. `learnerTraceFrames` reuses the same filename matching, source-version gate and line bounds as `learnerTraceLocation`; the latter now delegates to the frame list. Standard Python and pytest frames, Windows/native/browser paths and CR/LF/CRLF row positions are supported. Test, reference, library, ambiguous basename, invalid and out-of-range frames remain plain text. Unknown, checking, modified or absent source evidence cannot produce frame navigation. Immutable history without an editor callback also remains plain text.

Both failed-test details and run-level failures use the same diagnostic view. Full logs start collapsed. Opening a trace enhances only the verified implementation rows with native buttons; ordinary output stays coalesced text. Closing restores a single raw text value. This keeps long logs from generating a node for every output line. Frame selection uses the existing editor-location callback and source offset rules, while report grades and stored source evidence stay immutable.

The trace toolbar adds a wrapping toggle, enabled by default, and uses the common resilient clipboard hook. Copying submits the original full diagnostic string to the Clipboard API. Busy commands retain focus and deduplicate; an eight-second timeout, denied permission or missing API reveals a labelled read-only manual field without automatic focus. The native field selects its displayed text when focused; platform textarea newline normalization is independent of the original API payload. Locale changes retain the field, selection, trace scroll and wrapping preference. A replaced message starts a fresh collapsed lifetime, including A→B→A changes, and cannot receive obsolete copy feedback. Already started browser clipboard writes cannot be cancelled, but obsolete UI acknowledgements are ignored.

The new styles are imported with the deferred diagnostic component. Existing trace toolbar 40px targets/44px coarse-pointer rules are retained. Frame links use inline monospace text, dotted underlines and visible keyboard focus. Manual output uses a bounded, resizable field; unwrapped logs scroll within the trace. No new dependency, report schema, grade, judge/runtime, account or database change is required.

`check-trace-navigation.mjs` checks frame rows, prior deepest-location behavior, newline variants, repeated calls, native/Windows/browser matching, source gates and invalid/library/reference frames. It mounts the real report and workflow components, selects caller/helper code offsets in a native editor, edits the source state, checks stale links disappear and verifies the rerun receives current code. It also covers run-level diagnostics, escaped output, collapsed enhancement, a 20,000-line log with coalesced text nodes, wrap/locale/scroll continuity, exact copy payload, duplicate/busy controls, manual selection, timeout/retry, replaced-message/unmount isolation and immutable report data. Existing source-location, App/editor, report and clipboard checks remain in the full frontend suite. Both edition builds, emitted CSS/dependency inspection and temporary backend HTTP/session/SQLite checks supplement the DOM checks. No browser rendering, hit-testing, OS clipboard or new numerical judging claim is made.

GitHub workflows stay manually disabled. No CI run, release tag, deployment or production application write is created.
