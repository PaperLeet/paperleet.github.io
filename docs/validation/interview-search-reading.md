# Interview search reading

Applied experience searches now use the shared literal title highlighting and bounded Markdown search excerpts already used by community feeds. Cards show a matching passage rather than always clipping the opening paragraph. Prose, headings, code, formula source and table text remain distinguishable. Link destinations, image labels and raw markup do not become visible search evidence; a source-only or out-of-preview match gets an honest explanatory note.

Search results show original published text. Automatic translation is paused for cards with an applied query, so translated words cannot hide or fabricate the match. Returning from a translated full thread restores original highlighted evidence. Clearing the query restores normal translation behavior. Unsubmitted search edits do not change cards, requests, page or applied scope. Whitespace-only incoming queries follow the service’s unfiltered behavior and do not show a source-search notice or highlights.

The experience hub explains this source-text behavior once above the feed. Metadata, anonymous identity and affiliation remain independent of highlighting. Existing inline full-post reading, keyboard collapse, comment/bookmark controls, linked practice and exact post/login/reading return URLs are reused. Source statistics keep their established company/role/period/context scope; a text search does not redefine contributor counts. Native modified, repeating and composing Escape events leave the search draft intact across community and interview search controls.

`check-interview-search-reading.mjs` renders the actual StrictMode hub and community thread. It covers late prose matches, rich-source previews, literal markup and hidden-source safety, applied/draft query distinction, saved/page/context and practice/login returns, anonymous affiliation, cached translation boundaries, inline reading/collapse and list focus return, locale continuity, stale query/account requests and unchanged private code, caret, scroll and draft. An optional disposable HTTP/SQLite flow verifies real public matching, structured filters, anonymous affiliation and full-scope statistics without changing the database. Existing search, preview, reading, community and interview regressions remain required. Physical browser layout, native IME/clipboard and live translation providers are not claimed.

The refreshed OAuth page retains its prominent provider/email layout and capability-aware community guidance: confirmed open publishing explains that affiliation is optional, while older services describe publishing access only after sign-in. Existing guest-to-account tests cover both literal capability states and unchanged native return links.
