# Live Markdown writing

Post and solution authoring, interview reports, full-thread replies, inline comments and post/reply editing now offer an optional third mode: **边写边预览 / Live preview**. Write remains the default. Live preview keeps the existing source textarea mounted alongside the real community Markdown renderer, including math, safe links and code reading controls. The editor container determines layout: at 720px or wider, source and preview occupy equal columns; narrower editors stack them. The preview scrolls independently with a 480px maximum height. Source styling targets only the authoring textarea, preserving manual code-copy fields in rendered previews. Native mode buttons retain 44px targets and keyboard focus indicators; compact containers hide the supporting caption.

The source state updates immediately; `useDeferredValue` lets the preview catch up separately. A busy preview is labelled while retaining only the same editor scope's previous output. Submission and shortcuts always read the current source, never the deferred preview. Empty source clears prior output. Account and draft-context keys start a fresh scoped editor, preventing cross-owner or cross-context deferred output and view snapshots. No draft schema, API payload, automatic publication or storage write is introduced by changing the mode.

Mode changes preserve the native source element, selection direction and both scroll axes, and respect newer focus choices. Inline minimization keeps that element hidden and mounted. Collapsing the entire comment section unmounts it; reopening restores the ephemeral live-mode snapshot and the parent's existing caret/scroll recovery only for the matching scope and source. Locale changes preserve editor and preview nodes. Existing busy/disabled controls, formatting/undo, length limits, IME guards, publication acknowledgements and retry receipts remain in use.

The six existing mounted authoring fixtures exercise live mode, selection/scroll and storage continuity before their original preview, undo and publication gates. The solution-publication fixture publishes while live mode is active and checks the exact authored body. `check-live-writing.mjs` mounts the real renderer and inline comment component: it covers real formulas/code, urgent source versus deferred output, current-source submission, empty clearing, locale/focus continuity, busy gates, account/context isolation, snapshots and minimize/collapse/reopen behavior. Its first run incorrectly assumed minimization unmounted the source; the corrected assertion checks the existing hidden-but-mounted contract. The original failure log is retained outside the repository.

Full frontend and private regression suites, both edition builds, emitted CSS/container-query checks and read-only preview source inspection supplement the mounted checks. React structure, hook ownership, stable scope keys, native labelled controls and deferred rendering were reviewed. These checks do not establish browser-rendered geometry, hit testing or OS behavior. Existing asset limits and dependencies are unchanged. GitHub workflows remain manually disabled; no CI dispatch, release tag, deployment or production application write is made.

The final full run exposed an existing anonymous-profile test that read the previous page after a fixed 10ms click delay. A separate JSDOM event-loop diagnostic reproduces a changed hash before the hashchange-driven page render. The fixture now waits, within its existing two-second bound, for the actual anonymous thread/profile destination before retaining all original URL, privacy, focus and exact-reply assertions. The same wait is applied to the parallel anonymous-reply route. No production navigation change is made; the original failed full log and independent diagnostic are retained outside the repository.
