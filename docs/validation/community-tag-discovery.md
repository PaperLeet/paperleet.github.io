# Community tag discovery and writing continuity

The existing managed community tags now have a searchable native disclosure instead of a bare select. The browser searches public Chinese/English names, stable identifiers and descriptions, with case-insensitive NFKC matching. It shows active tags and the currently selected paused tag; counts refer to available tag definitions, never post popularity or company frequency.

Choosing a tag keeps the current module, board, solution/discussion view, search, saved/following scope, publication period and order, and starts at page one. The problem page keeps this state locally without navigating away from the learner's code. Selecting the current tag or searching tag metadata does not issue another feed request or any mutation. Escape clears a local tag search first, then closes the disclosure; composition guards preserve ongoing IME input. Locale changes and background reads do not move focus.

Selected tags display their public description. Paused tags explain that historical posts remain readable and new publications need an active tag. An unknown tag retains the requested filter and offers configuration refresh or explicit removal. If the server does not advertise literal `community_taxonomy: true`, tagged views do not issue unsupported feed requests or display an unfiltered feed under a tag heading. Removing the unsupported tag keeps the remaining view. Existing strict response-tag and per-post membership checks remain in place.

A fresh composer starts with the current active tag when its metadata is available at opening. Restored drafts take precedence. Switching filters, opening/closing the tag browser, or receiving metadata later never adds/removes tags in an already mounted draft. A contextual note explains when the browsing tag differs from a kept draft. Paused and unknown tags are not seeded. The existing server still validates every publication and captured retries keep their exact original payloads. Tag-only defaults do not create phantom writing drafts.

Verification combines controlled React/JSDOM with the actual shared feed/composer and a disposable loopback account/community API and SQLite database for tagged publication. Local build profiles and the complete frontend/backend gates are recorded outside the repository against frozen commits. No browser automation, rendered-geometry, native-focus-trap, physical IME, OS clipboard, live-provider or production data claims are made. CI, release tags and deployment remain held.
