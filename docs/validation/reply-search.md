# Search inside discussion replies

Full discussions, including solution and interview threads, now offer a local search across the complete reply array already supplied by the server. Matching includes the Markdown source (including code and formula source) and the displayed public name/username. Anonymous identities contribute only generic anonymous labels, even if a malformed caller retains hidden identity fields. Internal IDs, timestamps, affiliation records and unpublished drafts are excluded. Queries use bounded 200-code-point input, literal whitespace-separated AND terms, NFKC width normalization and lowercase matching; regular expressions are not interpreted. This is source search, not a semantic or rendered-text-only search.

Typing leaves the applied result list unchanged until submission. The shared search control retains its existing IME/Enter/Escape protections, now with optional labels and disabled guards. Busy publication/refresh and active reply edits lock both the field and actions; synthetic submissions cannot apply a new filter while locked. The full discussion has an accessible search name and content/code/author placeholder. Search combines with author-only and oldest/newest order, resets the mounted batch and displays accurate matched counts and a dedicated no-match recovery. Clearing search keeps the other filters.

A parent or just-published reply outside the current search remains reachable through the existing reading navigation. Revealing it temporarily clears local filters; Return restores the applied query, author filter, order, batch, source trigger and viewport anchor. If the original row is edited so it no longer matches, return clears that query to keep the row reachable. Missing origins retain the existing truthful fallback. Search is ephemeral per thread/account, never enters URLs/storage/API payloads and does not issue additional requests. The publishing textarea, its caret, selection direction and both scroll axes remain intact.

Search indexes are built only while a query is active and reused across term changes against the same reply array. Raw strings stay in React/text controls; no HTML injection or regular-expression construction is introduced. Styles remain in the deferred discussion bundle, with a full-width 44px search field, readable body type and existing 40px/44px pointer targets and keyboard focus rules. There are no dependencies, judge/runtime changes, account/database migrations or asset-budget relaxations.

The existing full discussion fixture retains every earlier assertion and adds full-thread versus mounted-batch search, code/Unicode/literal contracts, anonymous identity exclusion, submit-before-filter, author/order intersection, accurate empty counts, batching, parent/return continuity, changed-origin recovery, disabled-edit protection, account reset and immutable data. It checks exact composer/draft/selection/scroll/URL continuity and no extra reads or writes during search. The first new changed-origin assertion incorrectly expected row focus; the existing return contract restores the surviving original parent button. The corrected assertion checks that exact trigger and the original log is retained outside the repository. Existing feed-search IME and all discussion/reading/privacy tests remain in the full suite. Builds and emitted CSS/dependency checks supplement React/JSDOM; no rendered-browser geometry or hit-testing claim is made.

GitHub workflows remain manually disabled. No CI dispatch, release tag, deployment or production application write is created.
