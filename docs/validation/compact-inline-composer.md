# Compact inline comment composer

Initially opening a card’s comments now starts with a compact writing entry instead of the complete Markdown form. The existing latest-three preview and incremental expansion stay in place. “Write comment”, the compact entry and each comment’s “Reply” action open the editor directly. Once the preview is loaded, entering, minimizing or resuming its editor adds no detail read or write.

The editor has an explicit minimize control. Its native form remains mounted but hidden, preserving the textarea, draft, selection, scroll and pending publication. The compact entry distinguishes a fresh comment, retained draft, unconfirmed publication and failed draft persistence. No private body text is copied into the compact entry. Pending publication retries retain the same publication identifier. The minimize control is disabled during in-flight requests, and hidden forms cannot publish through shortcuts or synthetic submission.

Opening and minimizing use guarded commit-time focus handoffs. They account for the native focused-control fixup when the triggering control becomes hidden, while yielding to a newer focus or route choice. Form IDs are unique per card instance, control relationships are explicit, account transitions still unmount private state and guests retain the sign-in path. Styles enforce the native hidden state, support narrow screens and reduced motion, and reuse existing theme tokens.

The saved-interview integration enters through the same compact control and preserves independent bookmark state and source routes. The maintained card checks cover the compact default, real entry controls, hidden publication guards, mounted DOM/caret/scroll preservation, newer focus priority, unavailable storage, pending publication recovery, multiple bilingual card instances, anonymous affiliation, reading returns and existing account/owner isolation. Isolated React + AccountProvider + real HTTP/session + SQLite integration checks actual persistence, no added requests, held acknowledgements, minimized pending retries and one persisted reply. Synthetic local accounts only; no production content is written. DOM verification does not claim browser visual review.

Release validation retains the complete frontend suite, local and hosted builds and existing bundle budgets, native/browser-WASM/backend gates, quality-gated Pages and immutable online asset/API revision checks.
