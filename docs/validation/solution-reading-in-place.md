# In-place solution reading

Problem solution cards use a native title disclosure to read the complete solution in the existing left pane. Code, formulas, article headings and code-copy controls reuse the community Markdown reader. A separate ordinary link retains the canonical full-thread return context. Community feed and profile cards keep their existing title links. Card reactions and inline comments remain outside the disclosure, preserving their component state as the body opens and closes.

The embedded outline starts collapsed, uses one column even on a wide desktop, and folds after a section jump. Its current section follows the actual reading pane's scroll and resize events. Jumping or returning to a collapsed card scrolls the pane vertically without changing the practice URL or its horizontal scroll. Standalone discussions keep page scrolling and their existing desktop outline layout. Scroll listeners, animation frames and resize observers are cleaned up; late observer callbacks are inert.

Collapse and Esc return focus to the title only when the initiating focus and URL still match. Newer focus in the editor wins. Modified, repeated and IME Esc events, and keyboard events from editable descendants, are left alone. A changed body or account cannot revive an older open reader. Switching locale preserves the exact open body. The explicit Back to code action uses the existing workspace editor action, preserving the entered code and editor selection instead of inserting a solution.

Mounted React/JSDOM checks exercise the actual feed/card/Markdown/outline, unchanged practice source/selection/both scroll offsets, pane scrolling with a modelled viewport, section highlighting, native disclosure state, local code action, focus/route/body/account guards, cleanup and standalone fallback. Existing standalone discussion and solution-publishing checks are retained. Full frontend checks, both builds and emitted CSS/manifest inspection verify integration under existing budgets. These are DOM/source/declaration checks, not a browser-rendering, hit-testing, manual keyboard/OS input-method or live clipboard claim.

No community API, persisted format, private service, runtime, exercise, dependency or workflow changes are introduced. No production posts, CI dispatch, release tags or deployment are created. Publication remains held with workflows disabled.
