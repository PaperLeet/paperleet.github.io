## Runtime fidelity

- Bicubic interpolation implements coefficient -0.75, both align-corners conventions, negative source coordinates and replicated edge samples. Overshoot is retained. Explicit sizes and noninteger scale factors follow their respective native coordinate rules, including recomputed scale factors.
- Area resize and adaptive average pooling use the actual floor/ceil averaging regions for non-divisible sizes, overlapping regions and upsampling. Three-dimensional pooling, four-dimensional interpolation, strided inputs, singleton spatial axes and empty batches are covered. Input gradients use the transpose of the separable resampling matrices; forward and backward independently choose the multiplication order with the smaller intermediate. A 1×2048 to 2048×1 case retains native values and analytical gradients without allocating a 2048-square temporary. No numerical-gradient or lower-resolution substitute is used.
- Lookup uses supplied codebook values, supports int32/int64 and scalar/empty indices, and accumulates repeated-index gradients. Padding suppresses only the backward contribution, not the stored forward value; optional frequency normalization follows native behavior. Embedding renormalization/sparse gradients, antialiasing, other interpolation modes and unsupported dtypes remain explicit server paths.
- Allocation caps bound the interpolation matrices and output. NumPy integer output sizes are converted to Python integers before size arithmetic, so extreme sizes cannot overflow those checks.
- Unique supports frozen real/integer/bool values, CPU sorting behavior, dimension-wise results, inverse/count metadata, NaNs, scalar and empty inputs. Differentiable unique and unsupported empty dimension-wise cases explicitly require the server. MoGe's original no-grad solver remains frozen.
- Remainder supports native sign conventions and analytical broadcast derivatives. Integer scalar promotion retains the array dtype; division by zero is rejected for integers. Integer sine/cosine correctly produce float32 before VAR's explicit float64 conversion.
- Array storage addresses distinguish clones from aliases and return zero for empty arrays. The maintained VAR snapshot test therefore checks real independent allocations rather than a fabricated identity counter.

Contracts were checked against official [interpolation](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.interpolate.html), [embedding](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.embedding.html) and [unique](https://docs.pytorch.org/docs/2.14/generated/torch.unique.html) documentation and the installed native interpolation coordinate/kernel definitions. Differential comparisons used installed PyTorch 2.14.1. The long singleton-axis float32 reduction uses a native float64 VJP on identical rounded arrays as its precision oracle; the native float32 reduction accumulates the 2,048 contributions in a different order. Ordinary float32/float64 cases retain direct native value/VJP comparisons. The production Docker PyTorch 2.6.0 image was not exercised.
