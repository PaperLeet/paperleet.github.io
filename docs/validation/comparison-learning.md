# Company comparison learning and practice

The personal projection uses existing status validation on loaded problems and the
current owner's saved workspace. Valid accepted/native/historical browser evidence
can pass; failed, malformed, wrong-problem and incomplete grades cannot manufacture
completion. Empty changed code is started; untouched starter text is not. Source
concepts with missing problem metadata retain links in All and are excluded from
known personal states. Progress/catalog unavailability preserves the filter without
claiming zero matches or completed work. Full progress totals require all source
metadata and confirmed personal progress.

Study serialization now covers applied company comparisons using the existing
canonical batch-view predicate. Ordinary company/report views still omit it.
Personal-only filtering retains the local or captured batch and unapplied company
search. Public pair/view/cohort changes keep their established retirement rules.
Direct practice captures the matching public module order, and existing navigator,
next-step, sign-in and library returns keep the exact scope. Shared batch links clear
the sender's personal filter; shared view copy explains receiver-owned progress.
No personal grade/code/state counts are sent in public reads or serialized in URLs.

The check exercises actual hub/native controls and practice navigation, as well as
model boundaries, metadata/progress errors and retry, filtered-empty versus absent
evidence, source-count/order immutability, current-owner isolation, native element
continuity, locale/code/caret/search/draft preservation and zero writes. The optional
HTTP bridge reads actual InterviewService summaries from two synthetic local posts;
it does not simulate positive API result presentation.

Verification is TypeScript, React/JSDOM and disposable HTTP/SQLite, not native browser
layout, physical focus/IME/clipboard, real mail/OAuth or production verification.

A separate before-fix component probe reproduced successful retry unmounting its
button and dropping DOM focus to body. Recovery now synchronously focuses a stable
local h3 before invoking the callback. There is no delayed focus effect: successful
button removal retains that target, while newer editor focus/caret takes precedence.
The actual hub check covers both progress and catalog recovery and the newer-action
case. The before-fix observation remains tied to its original source commit.
