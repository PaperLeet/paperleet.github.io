# Direct failure selection

The fix/verify summary previously offered only sequential arrows. A report with many failures required repeated actions to reach a later diagnostic. A native select now lists only failed tests plus an interrupted-run entry, in the same existing report order. It shares selection with the arrows, count, diagnostic, numerical comparison and verified implementation-location action. Selecting an entry does not run tests, navigate, focus the editor or mutate the report.

The picker has a localized accessible name and full native option labels. Its flexible grid shares space with the existing arrows/count and wraps below the heading when the reading pane is narrow. Shared readable type, theme tokens, focus rings and coarse-pointer 44 px controls apply. Navigation is disabled while a run is active; old comparisons and unverified source locations retain their existing guards. A new report resets to its first failure, and a single failure needs no picker.

The existing complete UI checks include a native React/jsdom interaction regression. It fails on the preceding implementation and covers distant selection across fourteen failed tests and one passing test, run interruptions, arrow/count synchronization, exact-source location, locale continuity, changed/running guards, replacement reports and single-failure behavior. The mounted editor, draft, selection, scroll and route are preserved; no run or edit action fires during selection. These checks are not browser visual QA and create no production data.

An additional isolated integration check uses the real native GroupNorm judge: the unchanged starter produces eleven failures, the production report parser and SHA-256 source fingerprint verify the report, and selecting its last failure locates the actual unimplemented learner line. Replacing the implementation makes the old location unavailable. After an explicit run callback, the corrected reference is judged by the native runner and produces eleven passing tests; the source-bound success clears the picker and old diagnostic while retaining the editor. This verifies the judge/report/React callback boundary; it does not claim browser UI or account API execution.
