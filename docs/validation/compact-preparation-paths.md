# Compact preparation path cards

Preparation module lists use three initial rows and a native disclosure for the remaining links. The selected path starts expanded so a direct path link or a source return keeps later modules visible. Other paths begin compact. Full-path progress, completion, unavailable-module notices and the resume action remain independent of disclosure state.

Native details/summary controls retain mounted links and their source URLs, expose platform keyboard semantics, and place newly revealed links immediately after the summary in focus order. Explicit native expansion or collapse survives progress and locale updates within the page. It adds no storage, global event listeners or API reads/writes. A new document uses the selected track to reveal the source path rather than narrowing company or concept filters.

Styles explicitly hide closed content and the inactive summary label, apply the same row spacing to initial and expanded links, keep coarse-pointer controls at 44 CSS pixels minimum, and restrict arrow transitions to users who permit motion. Existing theme tokens and selected-path ordering remain intact.

Maintained interaction checks cover default overview density, selected-path source returns, native expansion/collapse, focus order, link identity and unchanged scope/storage, fresh progress, missing catalogs, short paths and bilingual updates. Isolated React + AccountProvider + HTTP/session + SQLite integration reads the actual stylesheet, checks hidden/open computed display, performs later-module practice/source round trips and confirms unchanged report/contributor evidence. No production content is written. DOM and CSS checks do not claim browser visual review.

Release gates retain the complete frontend suite, local and hosted builds with existing bundle caps, native/browser-WASM/backend checks, quality-gated Pages and immutable served asset/API revision verification.
