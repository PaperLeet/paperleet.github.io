# Company comparison browsing

The company comparison panel now has a local finder for both native company selectors. It searches the loaded public catalog by Chinese name, English name or identifier, with the existing literal Unicode-normalized matcher. Typing only narrows the option lists: it never changes the selected pair, public comparison rows, filters, URL or practice group. Each selected company remains available outside the current matches; the company selected on the opposite side stays disabled. No-match feedback and a local clear action provide recovery without discarding the pair.

The finder remains local to its account and comparison panel. Own pair confirmations, locale changes, sorting/context changes and panel collapse keep its text. A different shared/back pair or account retires that text. Clearing the comparison also clears the finder. Input is bounded to 100 code points after composition, ordinary Enter stays out of surrounding forms, and Escape clears only this finder. The page-level company directory search retains its existing meaning.

Large comparison tables still reveal at most 12 additional concepts at a time. Expansion now focuses the first newly revealed concept link and reveals it vertically and horizontally. A separate, stable “Show first 12” control is available before reaching the end, so users can compact early. Explicit compaction keeps focus on that control; it remains focusable with aria-disabled when already compact. Existing workspace-intent guards make queued focus yield to newer input, scrolling, focus, navigation, owner/scope changes and unmount. Counts and table controls are linked through native IDs and accessible descriptions. The comparison does not change its public evidence or write practice data while browsing.

Validation includes the actual React components in StrictMode and the full 18-company bilingual/identifier catalog, retained native choices and table rows, Unicode/literal/no-match input, composition/Enter/Escape, own/external route distinction, owner/locale/collapse boundaries, bounded batches, early compaction, newer focus/scroll/navigation cancellation, and unchanged private text/caret/scroll/storage. The existing real interview-hub comparison suite also verifies its source links, URL sharing/login returns, error/retry guards and no extra requests. A disposable HTTP/SQLite scenario supplies unmodified source statistics for 28 maintained exercises from six valid synthetic reports before running the same comparison UI checks. The component itself intentionally makes no request when searching or expanding.

All four build variants and the full application checks qualify the frozen public commit and backend core pin. This change stays in deferred interview code and adds no backend endpoint or numerical execution change. Existing SDK evidence remains attributed to its original execution commits; no fresh native/WASM SDK execution is claimed. Physical browser layout, OS focus/select/IME behavior and live provider authentication are outside these DOM/source/HTTP checks. This wave does not deploy or dispatch CI.
