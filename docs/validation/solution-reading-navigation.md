# Adjacent community solution reading

Expanded community solutions in a practice workspace provide previous/next actions and the current ordinal within the applied result set. Existing expanded approaches and the solution composer remain mounted while stepping inside one page. Crossing a page retains the module, search, following/saved, tag, publication period and sorting state and uses the existing read-only feed request. The workspace URL, practice code, grades, publishing receipts and draft storage are not changed by reading navigation.

A step captures the originating control, owner/filter scope, source result identities, page and current intent. The selected destination opens and the notice removal commits before its native summary is focused and revealed in the correct page or independent workspace scroll surface. New input, focus, keyboard or pointer intent, including events stopped by an editor, takes precedence. Hidden views, a reference tab and a delayed response offer explicit continuation. Unmount, route, account or filter changes retire the old request. Failed reads keep the existing list retry. Explicit retry renews only the pending reading intent; a new editing action during retry still takes precedence and leaves a labelled continuation with its destination title.

Pages are validated before adjacency is offered. Empty, incomplete, unavailable and out-of-range targets have truthful recovery. If a newly inserted result creates page overlap, the original source identity anchors its adjacent item within the new page. A changed result count without that source requires explicit current-result recovery. This is navigation through current server results, not a snapshot cursor or a record of reading completion. Dismissing recovery retains a fully visible reading anchor. No browser storage record or new API mutation is introduced.

`web/scripts/check-solution-navigation.mjs` renders the actual StrictMode problem panel, Community feed and solution cards. Controlled tests cover local and cross-page traversal, exact filters, retained drafts and native selections, response loss/retry, source and result-list changes, account/route/filter retirement, stopped event propagation, hidden/reference views, notice commit geometry, dismissal, page/pane scroll choice, locale and boundaries. Existing actual App retention and reading checks remain in the full check command. Verification uses React/JSDOM and disposable HTTP/SQLite separately; it does not claim browser rendering, physical IME, OS clipboard or device behavior.
