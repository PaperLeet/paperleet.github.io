# Time-budgeted interview practice

The frequent-concept list, curated preparation lists and applied company comparisons offer a closed-by-default “Plan for your available time” disclosure inside the existing practice batch. It accepts 1–240 whole minutes (including fullwidth digits) and offers 30/60/90/120-minute presets. Closing and reopening the disclosure keeps the current visit's budget and mode. Changing its actual scope or account starts a fresh planner.

Planning previews additions in the current complete filtered list order, including concepts beyond the compact displayed rows. It counts existing selections first and appends only after explicit confirmation, preserving their order and allowing at most six concepts. It uses a greedy fit in the existing order, not a global packing optimum or a new claim about company frequency. Exercise estimates are approximate; missing estimates never count as zero.

The default adds concepts not yet passed. A passed-only list defaults to review mode. When progress is unavailable, users can explicitly include all exercises; an unresolved learning-state filter still cannot be bypassed. An unavailable selected module or missing selected estimate blocks time planning without discarding the user's choices. An over-budget selection, full batch, no remaining concepts or insufficient time offers an explicit explanation. Candidates without estimates are skipped and counted.

Applying recomputes from current catalog metadata, candidate order, derived learning state, selected order, scope and account. Queued manual changes, duplicate activation, changed progress/estimates/cohort and retired component instances cannot apply an old proposal. Only public module identity, estimates and derived state enter the local model. Raw source code, reports and unpublished community drafts are not serialized. No planning preference is written to a URL, storage or the service. Starting practice retains the existing exact public-number queue, login return, module picker and next-step behavior.

`web/scripts/check-interview-budget.mjs` adds five registered controlled React/JSDOM and pure-model check groups: budget/order/limit invariants; actual ranking-to-practice flow; queued and stale proposal rejection; unavailable/progress/bilingual input recovery; and company comparison/hub integration. Optional `PAPERLEET_INTERVIEW_BUDGET_HTTP` runs the actual hub against a disposable real public summary endpoint with maintained catalog estimates. This verifies browser-independent component and HTTP behavior; it does not verify rendered device geometry, physical IME, OS clipboard or live identity providers. Existing manual batch/comparison checks remain required. The planner and its styles stay outside the initial three-asset startup graph.
