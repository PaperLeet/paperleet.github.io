# Discussion sharing recovery

Post and reply copy controls now show a focused, deduplicated busy state and release a clipboard request after eight seconds. Denied or missing clipboard access exposes the exact canonical URL in a read-only field; focusing it selects the URL for normal platform copying. A failure does not move focus automatically. Both languages preserve the manual field, selection and horizontal scroll. Invalid origins or post/reply identifiers report an inline error instead of leaving an older manual URL visible or allowing a preparation exception to escape the click handler.

External share URLs retain only the frontend origin/path, post and optional reply. They omit credentials, the page query, feed searches and profile return context. This wave adds strict post-ID validation to the existing share helper; valid routes and login continuations are unchanged. The separate **View reply** link continues to retain validated local return context, including solution lists, profiles and interview views. Changing post, reply or local context starts a new sharing lifetime. Locale changes preserve it. No reply, social reaction or unpublished draft is sent when copying.

The existing code-snippet and interview-filter copy actions now reuse `useClipboardCopy`. It captures each explicit payload, deduplicates rapid commands, retires timed-out requests independently of retries and checks the current URL before acknowledging a completion. History listeners are installed only while feedback is active and are removed when it retires or unmounts. A delayed notification for the already current URL cannot cancel a newer command. Callers retain their existing content/owner keys and product-specific manual fields and messages. A browser clipboard write already started cannot be cancelled; only its obsolete UI acknowledgement can be ignored.

Discussion sharing has a deferred stylesheet with wrapping rows, 40px controls (44px for coarse pointers), 15px supporting text at the normal 16px browser base, a 44px manual field and visible keyboard focus. The code-snippet wrapping, syntax renderer and interview-filter URL construction are unchanged.

The new mounted `check-discussion-sharing.mjs` covers exact public URLs and login round trips; invalid identifiers/origins; validated local return links; focused busy controls; duplicate commands; permission failure, missing support, synchronous failure, timeout/retry; locale/manual selection continuity; stale post/reply/A→B→A/context/history/unmount cases; idle listener and cleanup behavior. It also mounts the real discussion component and verifies that sharing a reply preserves its private draft, editor/caret, URL and reading position without fetching or mutating social data. The pre-change strict-ID regression is retained outside the repository as `discussion-sharing-baseline.log`. Existing code-snippet and interview-sharing tests run unchanged against the common hook, alongside the full frontend suite, both edition builds and emitted CSS/dependency checks. Verification uses JSDOM, local temporary backend HTTP/session/SQLite and source/build artifacts; no browser rendering, hit-testing or OS clipboard verification is claimed in this wave.

GitHub workflows remain manually disabled. No CI dispatch, release tag, deployment or production application write is performed.
