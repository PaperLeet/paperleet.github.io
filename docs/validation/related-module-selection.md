# Finding and selecting related practice modules

Solution publication now has a local search beside its required native module select. Search supports current public module numbers, Chinese/English titles and canonical module IDs, with NFKC case folding and literal AND terms. Copied numbered titles also match. Queries are bounded to 100 Unicode characters after composition ends. Searching does not select a module, edit a draft, change a route or fetch data. An existing selection outside the results is retained in a separate native option group; a missing/retired selection remains visible as unavailable. New publication still requires an explicitly selected current module under the existing validation. The result count excludes a retained out-of-search choice.

Interview creation and editing reuse the same search field and matcher. The initial list shows six concepts; search shows up to twelve initially, and explicit six-item increments expose every match. Counts describe the actual displayed and matching totals. Selection chips remain visible across searches, the existing twelve-concept limit and canonical publication order remain intact, and missing catalog metadata does not discard existing links. A newer authoring scope retires transient search through the existing parent keys; locale changes keep it.

The shared search field is a search landmark inside the existing publication form, without nesting another form. Ordinary Enter, including modified Enter, is consumed by this field instead of submitting the outer publication form. IME candidate confirmation is left to composition; composition/legacy 229 Escape does not clear the query. Explicit clear and non-composing Escape return focus to the same search input, keeping selections and writing intact. Disabled fields guard programmatic changes and clears as well as native interaction. Real browser/IME behavior is not newly exercised by this wave; synthetic DOM checks verify event cancellation and composition state contracts.

Revealing results focuses the first newly available option when the initiating control owns focus. Removing a chip focuses the next surviving chip, the previous chip, the search field or a stable heading when the catalog is unavailable. Disabled choices, newer focus intent, navigation and unmounted scopes do not receive stale focus. Results wrap into one column on narrow screens. Search, clear, reveal and choice controls retain 40px minimum interaction targets and 44px targets for coarse pointers; the shared field owns its input reset so surrounding form styles do not create another input border.

Validation includes the mounted `check-related-module-selection.mjs`, expanded real solution and interview composer checks, existing authoring/edit/receipt/privacy regression checks, typed local/hosted builds and emitted CSS/import-graph inspection. Tests cover all published bilingual/copied-title/ID matches, Unicode/literal multi-term search, full browsing, required empty selection, retained nonmatching and missing selections, Enter/IME/Escape/clear, selection limits, focus guards, locale/disabled/owner scopes and exact reflection/caret/scroll/storage continuity. The tests use local fixtures; no posts are published to production. No screenshot, rendered geometry, hit-testing or OS UI verification is claimed.

Workflow execution and production publication remain held under the user's instruction. This wave adds no API/schema/runtime/dependency changes.
