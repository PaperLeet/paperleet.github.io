# Location and actual interview-month context

An optional disclosure applies an author-provided location substring and an inclusive actual interview-month range to public reports, frequent-concept statistics and company comparisons. Publication period remains a separate condition. Empty date endpoints are unbounded; a constrained month range excludes experiences whose author did not supply a month. Curated practice remains labelled as curriculum, not regional/company evidence.

The disclosure keeps unsubmitted edits in memory for the current account visit, across unrelated browse changes. Nothing is requested until explicit apply. Native fields, composition-aware submission, range validation, reset-to-applied values and clearing preserve ordinary keyboard flow. Applied context survives canonical share links, source previews, captured practice queues and sign-in returns. Changed contexts retire comparison batches even when the new source mentions the same module. List and source cards display actual month and public location alongside the separately dated publication.

The service must advertise literal `interview_context_filters: true`. Unsupported or still-loading accounts retain active URL values and offer a clear action without sending unsupported scoped requests. Active responses must echo the exact bounded context; every feed/source-preview item must also match its location/month. Old unfiltered responses without an echo remain valid only for an unfiltered request. Stale paths, cancelled requests and wrong-scope responses cannot become current counts.

Location is a literal substring after NFKC normalization and default Unicode lowercasing; percent, underscore and quote characters are not SQL wildcards. Bounds are 80 Unicode characters for location and 1900-01 through 2099-12 for months. URLs reject empty explicit context fields, malformed or repeated keys, control characters and reversed intervals. No raw source, learner grade, unpublished post or account credential enters these filters.

Four registered React/JSDOM/model check groups cover input/URL/scope validation, actual hub draft/application, reports-to-sources/practice/company comparison, bilingual native input preservation, wrong-scope and unsupported recovery, abort/late-response behavior, and account retirement. Optional `PAPERLEET_INTERVIEW_CONTEXT_HTTP` replays public reads against an actual disposable JudgeHandler/SQLite service. Backend service/HTTP checks verify distinct-author counts, inclusivity, unknown dates, publication-time composition, saved/disabled-user visibility, literal matching and anonymous identity masking. Real signed provider callback fixtures verify exact Google/Microsoft return context without contacting live providers. No browser rendering, physical IME/native focus trapping, OS clipboard or deployment is claimed.
