# Practice from a source post

Full interview threads now reuse the same linked-practice component as the interview feed. Titles come from the currently loaded public catalog in the chosen language. Missing and explicitly retired modules remain readable as unavailable context, without dead practice links. The initial two choices can be expanded to all linked concepts. Catalog retry restores focus to a newly available choice when the initiating control still owns focus; known retired choices retain a stable non-link focus target. Public metadata hydration does not replace or refocus the reply editor. Full-thread labels wrap and use the control text size; compact feed chips retain their existing layout.

Practice links in a thread, including a solution's existing practice action, now carry one canonical public post ID as their return source. No list search, profile name, reply target, private draft or nested continuation is appended. The workspace labels that return as **返回来源帖子 / Back to source post**. The same source is kept through sibling-module links, next-step links, paper detail and supported sign-in continuations. The Papers navigation still goes to the library. Missing-module and loading-error exits use the correct source label.

An earlier community/interview/profile list origin remains only in the existing bounded, owner-scoped tab reading record. A thread→practice→thread traversal preserves that record, so the thread can still return to the original list and its saved filters/page. Source-free recovery requires an already reading row (or the existing private anonymous-profile opening), matching post and owner. The actual workspace catalog entry must match the practice route before a reloaded record is rearmed. Outgoing thread effects do not erase a newer practice traversal. Different owners, unrelated posts/routes and confirmed catalog mismatches retire the old record; unresolved catalog data remains neutral. No storage schema, lifetime, draft payload or progress authority changes.

The public route parser and private OAuth return validator accept only `community/<32 lowercase hex digits>` in this practice source position. Nested source filters, profile/reply parameters, external URLs, duplicate `from` values and malformed IDs remain invalid. Ordinary list, favorite and interview preparation contexts retain their existing contracts. This requires the corresponding private API change before new OAuth continuations are released; production publication remains held.

Validation includes:

- Mounted actual community feed/thread and shared metadata, practice module navigator and next-step traversal back to the thread/list, including anonymous affiliation, retained reply writing and private owner isolation.
- The actual App fixture verifies English/Chinese source labels, correct Papers navigation, error/paper-detail exits and unchanged editor identity, source, caret and both scroll offsets when only the source post changes.
- Existing reading-controller regressions cover real hash transitions, title/list returns, saved/search/page context, reload, blocked storage, current catalog binding, expiry, missing rows and newer focus/route/account intent.
- Real local HTTP OAuth callbacks for both configured provider fixtures cover numeric, canonical module and paper practice destinations; negative tests retain strict source rejection.
- Complete frontend checks, private regression tests, typed local/hosted builds and emitted CSS/import-graph checks. No production posts, credentials or deployed data are changed. These are source/DOM/CLI/local HTTP checks; no rendered browser geometry, hit-testing, screenshot or OS/IME verification is claimed.
