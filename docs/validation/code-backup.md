# Portable workspace code backups

The navigation now opens a deferred code-backup dialog. It exports the current owner's loaded drafts, conflict sources and browser recovery versions, deduplicated by module and exact source. Empty files count as source. The JSON envelope contains only `format`, `version` and an allowlisted source array (`id`, `code`, `kind`); it carries no account identity, reports or grades.

Loading is explicitly per source: choose a file and module/version, inspect imported and current source, and start a download of the current source before replacing it. A source/owner/revision snapshot must still match. Browser replacements also preserve the displaced source through the existing transactional recovery journal. Hosted replacements use the existing private draft API and account/base-version checks. Imports retain earlier acceptance, which is marked as previous-code feedback where appropriate; imported reports cannot establish a pass. No source is executed until the user separately runs tests.

The whole file is bounded to 10 MiB UTF-8 and 1024 source entries before use. Unknown formats/versions, malformed rows and unsafe IDs fail with readable feedback. BOM-prefixed files are accepted. A source over 128 KiB can be previewed/downloaded but cannot be loaded into a module, matching the private draft limit. Retired/unknown modules remain downloadable and have no write action. Extra identity/report fields are discarded while reconstructing the permitted source shape.

Owner changes unmount the dialog and invalidate pending file reads; a newer file invalidates an earlier read. Saving, tests, conflicts and failed writes prevent replacement. Export is read-only and remains usable when saves or workspace hydration fail, with explicit partial-export scope while loading is incomplete. Browser-managed downloads are initiated by the app; a returned click alone cannot prove a file reached the user's disk.

- While the destination review was open, another tab changed its Schedules draft. The original review became stale and its load button disabled. Reviewing the latest source allowed import, with an exact backup download of that other tab's version. The imported source survived refresh and then passed the complete browser Schedules **8/8**, including all eight reference checks and five calibrated mutants. There was no grade before rerunning.
- Loading the empty Attention source downloaded its previous starter, retained that starter as a browser recovery version, and restored an actual zero-byte source across refresh. A separate CRLF/Chinese/emoji source loaded with exact bytes. The earlier Schedules pass stayed available and was labelled as belonging to previous source. A backup with forged owner/report fields could not replace acceptance; retired-module source had only its download action. A malformed file cleared the previous review and showed a readable error.
- Real private accounts/draft API: importing into Alice produced exactly **one** private draft with the expected code. Bob's exported source array was empty after switching accounts. SQLite inspection confirmed **zero** practice runs and no latest/accepted run IDs were created by import. No native judge submission occurred.
- A separate private fixture first rejected a draft save with 503, then rejected workspace GET after refresh. The authenticated browser recovered its pending cached source and exported it exactly while explicitly explaining the partial scope. Import stayed disabled. Failed-save/conflict reasons take priority over pending-save waiting text, so an error cannot leave users waiting indefinitely without a retry instruction.
- An intentional first-request 503 for the deferred backup stylesheet displayed the local failure message and kept normal per-module code downloads available. After saving finished, the guarded full-page reload fetched the panel successfully and retained the exact draft. SSR checks cover disabling reload while the shared workspace/learning recovery gate is blocked. The fallback provides no same-document import retry or unguarded page-reload button.
- Real 390 × 844 embedded browser viewport: the dialog measured **356 pixels wide**, spanning x=17…373, with 354 pixels of internal scroll width. Source selection, previews and load/download controls remained usable. This caught and fixed an old narrow-screen `nav button:last-child` rule that hid the new backup entry. Explicit file/select labels avoid including option text in accessible names. Escape closed the dialog and returned focus to its navigation button. Desktop and mobile screenshots were inspected.

Only frontend/workspace interactions changed. Numerical adapters, immutable browser bundles, suite identities and native grading are unchanged. Tests used disposable loopback services and source fixtures; no production state was changed. Browser validation covers the available engine on this host, not physical mobile devices or cross-engine certification. Test pages, servers and temporary credentials are cleaned up after validation.
