# Reply reading within the workspace

The reply reader now captures the scroll surface with its return anchor. In a problem's solution pane, parent-comment lookup, multi-hop reading returns, newly revealed batches and missing-origin recovery scroll that pane. Standalone community discussions retain native page scrolling. Anchors store positions relative to the pane edge, so moving the pane on screen does not invalidate a return. A shorter pane keeps the focused return control visible; partially visible origins retain their negative offset unless the focused control needs revealing. Removed or different panes cannot receive a stale anchor restore.

Long inline-comment collapse and comment-preview dismissal use the same surface-aware visibility helper. Opening or resuming a comment editor focuses without scrolling the outer page and then reveals the textarea within its pane. The existing per-thread draft, selection direction, textarea scroll and preview/minimize behavior remain intact. Reply navigation keeps its existing URL/focus/interaction-version checks: newer focus or wheel input wins over a queued jump. The bounded return stack remains ephemeral; no new persistent format, network request, global event payload capture or automatic publication is added.

The new mounted React/JSDOM flow uses the real card actions, reply hook, rich inline body and comment composer inside a modelled reading pane beside a retained practice editor. It checks multi-hop returns after the pane moves, notice-aware offsets, batch focus, long-body collapse, comment resume, exact draft/selection/vertical/horizontal scroll continuity, newer wheel/focus priority, surface identity and resize guards, unchanged practice URL, and zero outer-page scroll or publication. Existing standalone discussion, inline-comment, solution-reader, account and publication checks are retained. Geometry assertions use a declared test model and do not claim browser layout, hit-testing or manual OS input validation.

Complete frontend checks, both edition builds and retained compiled-style/deferred-graph checks qualify this frontend-only change. Community APIs, private backend, runtime, exercise data, dependencies and workflow source remain unchanged. Publication is held; no CI dispatch, release tag or deployment is requested.
