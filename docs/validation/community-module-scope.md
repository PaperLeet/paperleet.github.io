# Community module discovery

Standalone discussion and solution feeds now expose a native, collapsible module scope picker. It searches the already loaded public catalog by exercise number, Chinese/English title and canonical module ID, using the existing literal Unicode-normalized matching helper. It does not request posts or change the applied scope while typing or choosing an option. “View results” is a real local anchor that applies the chosen scope, preserves the content kind, board, tag, saved/following state, text query, publication period and order, and resets only pagination. Selecting the already applied module keeps its existing page. Same-module solution/discussion links also preserve the discovery filters.

The search narrows available options without silently selecting the first match. A selected option stays visible outside those matches. Missing/retired choices and catalog failures cannot cause a draft to navigate to an unrelated module; a visible message explains the disabled action, and choosing all modules remains available during an outage. Catalog retries are explicit. Feed/account remounts retire local selection/search drafts, while locale and catalog refreshes preserve them. Native select Escape is left alone; search Escape first clears its own query, and a second ordinary Escape collapses the disclosure. Composition, modified keys, stale routes and disconnected nodes do not trigger delayed navigation or focus changes.

The parent retains its existing topic/kind/account key. Embedded exercise discussions and solutions do not include this additional picker. The change stays in the deferred community graph; it does not add a service endpoint, change publication authorization or modify numerical execution inputs. Existing practice links remain available; this change does not claim new practice-to-feed scroll restoration.

Validation uses the real React components in JSDOM, including StrictMode, local anchor navigation, the complete 89-exercise public catalog and a disposable HTTP/SQLite CommunityService flow. The checks cover unapplied selection, preserved filters, same-scope pagination, no-match/retired/outage recovery, modified/stale navigation, locale/owner reset boundaries, native-select and composition event contracts, unchanged practice text/caret/scroll and embedded exclusion. Full application checks and all four production build variants also run against the frozen public commit and backend core pin. Existing SDK execution evidence remains attributed to its original execution commits; no new native or WASM numerical execution is claimed.

Limitations: JSDOM verifies DOM/event/state contracts, not physical layout, OS select/IME behavior, screen-reader announcements or real provider authentication. This wave does not deploy or dispatch CI.
