# Reading search results in discussions

Reply search covers the complete supplied public thread and intersects the existing author and order controls. Search is applied on submission. Public affiliation display names and their bilingual aliases use the same resolver as the visible identity badge. Anonymous names, usernames, identifiers, raw organization domains and unpublished editor content are excluded from the identity index.

Results show literal, escaped source excerpts with NFKC/case-aware highlighting. Excerpt whitespace is visually collapsed to prevent arbitrary blank lines from expanding result cards; original Markdown/code formatting is unchanged. Original grapheme boundaries are retained where Intl.Segmenter is available; the fallback preserves code points. A reply body has at most three excerpt windows, each at most 240 graphemes, with bounded highlight nodes. Long normalized matches can be clipped with continuation markers. Those markers are not search evidence. Oversized sources offer full reading instead.

Full Markdown remains mounted behind an explicit show/hide control during search. Clearing the search restores normal full reading. A new query or changed source requires opening that full reply again. Explicit first, previous and next match actions cross mounted batches in the current filtered order. Edit locks, newer interaction/focus and route changes guard navigation. Searching does not issue a request or write a draft, reaction, publication or URL.

`web/scripts/check-reply-search-context.mjs` exercises the mapping/privacy model and actual Community UI in controlled React/JSDOM: long sources, literal hostile markup, compatibility expansions, anonymous affiliation, batching, disclosure DOM retention, source refresh, account/locale changes and private editor/caret/scroll isolation. Existing reply checks remain in the full gate. This is source and controlled DOM evidence, not a rendered-browser/device/physical-IME/clipboard claim.
