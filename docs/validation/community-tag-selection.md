# Community tag selection and recovery

Administrator board/tag configuration now has a shared writing-side selection experience for community posts, problem solutions, interview reports and edits. Selected tags remain above search results, with a five-tag count and direct removal. Search matches normalized bilingual names, identifiers and descriptions. Metadata failure exposes one enabled retry outside the fieldset, preserving writing and selection.

New publications explain paused or unavailable selections before a mutation. Exact captured publication retries keep their original payload and request ID after metadata changes; newer writing remains a separate draft. Existing post edits distinguish retained historical tags, allow explicit removal and show current tags during stale-version review. A service without tag persistence cannot silently save a tag removal as a body-only edit. The server remains authoritative for eligibility, membership and idempotence.

Controlled React/JSDOM checks cover metadata recovery, pending removal, focus/draft continuity, normalized search, composition/Escape guards, queued selection bounds, retired capabilities, historical edits and captured retries. Disposable loopback HTTP/SQLite checks cover actual retained paused associations, explicit removal and corrected new post/interview publication. No rendered geometry, physical IME, native focus trapping, clipboard, device or live-provider validation is claimed.

Tag UI/CSS remain deferred; startup size limits are unchanged. Release workflows and deployment remain disabled until an explicit release.
