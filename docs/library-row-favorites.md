# Direct exercise-list bookmarks

Hosted general exercise rows expose an independent save button beside company sources when account capabilities support private problem bookmarks. Both controls are siblings of the whole-row practice anchor. Their shared action cell aligns with the table heading, uses 44px native controls, and follows the same responsive insets as the row. The existing row height and comfortable/compact density remain unchanged. Unsupported capabilities retain the company-source control without an empty save slot.

The optional row button uses the existing owner-scoped favorite store. Fifty visible controls share one initial private snapshot and one focus/storage watcher. Loading does not block company evidence or practice. Locale, page size, metadata sorting, filtering and page changes retain the current view; bookmarking itself never changes row membership or order. Unauthenticated links keep the exact canonical library view through sign-in.

Each action includes the exercise name in its accessible label and tooltip. The compact row surface hides the named-study-list launcher; existing workspace, saved-page and selected-company controls keep their default study-list behavior. Optional control loading reserves its slot. Failure exposes a local retry button while practice and company sources remain usable. Retry synchronously focuses the persistent company button; later loading never steals newer focus.

A busy save cannot duplicate a mutation. Saved appearance follows a validated server acknowledgement, including owner, revision, problem ID and operation direction. A lost response retains its original save/remove direction on explicit retry. Hidden/stale row actions and sign-in links refuse activation. Account/capability changes remove old controls; late old-owner responses update only that owner's store and cannot paint the current account. Already issued writes are not represented as cancelled.

Actual React/StrictMode list checks cover fifty shared controls, guest returns, independent company evidence, double-click deduplication, uncertain save retry, malformed-owner acknowledgement, locale identity, hidden/stale actions, account/capability/page changes and optional failure/retry. A disposable authenticated JudgeHandler/ProblemBookmarkService/SQLite flow uses two accounts, save/remove and simulated transport loss after commit; it verifies idempotent retry, owner isolation, unchanged public content/practice data and exact bookmark versions. No production data or physical browser geometry is used.
