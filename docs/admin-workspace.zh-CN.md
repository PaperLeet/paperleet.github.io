# PaperLeet 管理员工作台

登录管理员账号后，从右上角头像菜单进入「管理员工作台」，或访问 `#/community/admin`。入口只向正常状态的管理员展示，每次数据读取和操作仍由后端检查权限。

## 第一次使用

本地入口：[管理员工作台](http://127.0.0.1:5185/#/community/admin)。页面依赖账号服务；只打开静态前端不能获得管理能力。

管理员身份由服务端授予，页面不能把普通账号提升为管理员。正式邮箱登录使用服务端的 `PAPERLEET_ADMIN_EMAILS` 完整邮箱名单，并要求登录邮箱经过可靠验证；测试登录模式通过已有的 `paperleet_cloud.test_accounts create <登录名> --admin` 维护命令创建独立管理员。使用当前服务的数据目录和认证模式，不必为了体验工作台切换认证模式或清空数据。

登录后仍没有入口时，先核对账号是否为正常状态的管理员，以及账号服务是否返回 `admin_workspace: true`。权限不足、服务不兼容和读取失败各有明确提示，不会显示一套无法保存的假数据。

日常可从概览开始，依次处理举报、论文初审、候选版本，再查看操作记录。审核原因是内部记录；需要告知用户的内容填写独立的「给用户的说明」，避免把内部备注发给用户。

## 页面与日常工作

| 页面 | 用途 |
| --- | --- |
| 概览 | 查看待审数量、优先处理预览和常用操作 |
| 社区版位 | 新建或编辑中英文名称、说明、展示顺序，开放或停用版位 |
| 标签 | 新建或编辑标签，设置展示顺序和可用状态 |
| 举报审核 | 按待审举报人数排序，查看举报快照、当前内容与变更，决定保留或移除 |
| 用户管理 | 按公开用户名、昵称与状态查找，停用或恢复普通用户账号 |
| 论文审核 | 初审投稿是否适合进入生成，再审核生成后的具体候选版本 |
| 操作记录 | 核对管理操作的管理员、原因、时间，以及变更前后状态 |

首页「优先处理」分别预览最多三项待审举报、论文初审和候选版本。举报按待审人数优先，论文按提交时间从早到晚排列。点击预览进入具体案件或投稿；查看完整队列可以继续处理其余内容。没有待办时显示明确的空状态，网络错误不会被当成零条待办。旧服务未提供待办功能时保留原来的概览和完整列表。

## 审核规则

- 同一账号对同一帖子只计一次举报；举报人数多不会自动删除帖子。管理员需要查看证据、填写原因并作出决定。
- 匿名帖子仍隐藏作者用户名，公开 affiliation 按原规则展示；首页不显示举报人身份或私人联系方式。
- 版位和标签采用停用而非直接删除，旧帖关联继续保留，停用项目不能用于新帖。
- 停用用户会撤销登录会话，保留历史内容。账号状态变更需要原因和准确用户名确认；管理员账号受保护。
- 论文先通过初审，才进入适配与生成。候选内容需要另一次审核，审批绑定版本与内容包；新版本不能沿用旧版本的审批。审核通过后仍需满足验证、社区评审与发布流程。
- 操作基于当前版本并保留审计记录；网络结果不明确时可以重试原操作，避免重复执行。审核期间对象发生变化，需要重新核对。

## 可以继续扩展

下一阶段可以加入站内运营公告、版位置顶推荐，以及举报处理统计和审核时效。更细的管理员／审核员权限与批量操作应在角色规则和误操作恢复方案明确后再加入。

当前不自动删除高举报帖子，不自动部署论文，也未安排定期后台审核任务。质量检查与线上发布由维护者通过 tag 或手动流程另行执行，普通主分支推送不会触发这些工作流。

## 举报审核位置

工作台支持把审核状态、累计举报人数门槛（1／3／5／10）、页码和当前案件保留在链接中。刷新、重新登录或返回原链接后，可以继续核对同一队列与案件。切换案件不重新读取整个队列；「返回本页队列」保留筛选与页码。侧边栏也会记住本次访问的举报队列位置。

删除或处理内容后，当前页可能变空，可以明确返回最后一个可查看页。最多查看 501 页；达到范围上限后请缩小筛选。读取失败会显示重试入口，旧请求不能覆盖新筛选，也不会把错误当成空队列。旧服务不支持保存位置时，可以返回兼容队列。

链接仅记录位置，不包含审核说明、请求编号、账号信息或删除确认。恢复位置不会自动提交审核决定。

## 审核结果站内通知

兼容服务会把审核反馈放进已有收件箱。投稿者可查看审核决定、当时版本和已公开的审核意见，并返回投稿查看最新状态；历史版本通过不等于新版本通过，也不等于正式发布。

举报结案后通知本批待审举报人处理结果；移除现存帖子时也通知作者。通知不包含举报人身份、举报证据或内部审核说明。作者不会收到指向已删除帖子的失效链接，举报人可进入自己的举报记录。

通知与审核决定在同一事务内保存，重试原操作不会重复发送。启动服务不会为历史决定补发通知。打开收件箱或展开审核意见不自动标记已读；标记操作只覆盖已观察到的消息范围，新到的审核结果仍保持未读。旧版客户端也不会误标记它看不到的审核通知。

## 给用户的处理说明

兼容服务提供独立的「给用户的说明」，最多 500 个 Unicode 字符。新版页面移除帖子时需要填写说明，并展示接收范围；修改说明后需要重新确认移除。内部备注不会自动复制到这段文字或通知中。说明发送给本批待审举报人；移除现存帖子时也发送给作者。原帖已经不存在时只通知待审举报人。

结果不明确时，待确认区域显示原操作、原接收范围和已捕获的说明。重试沿用原内容，后续修改仍是未提交草稿；成功后也不会把新编辑误当作已发送内容。草稿仅保留在当前选中案件的这次访问中，离开或刷新不承诺备份。

接收人可以在通知里展开说明；举报人还可以在「我的举报」回查。说明绑定自己这次举报的首次审核，后续新举报和新审核不会改写旧说明。旧客户端可以继续提交不含该字段的原命令；历史审核不会用内部备注补发用户说明。
