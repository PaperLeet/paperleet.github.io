# Search comments directly in community and experience feeds

An opened comment preview now offers a local search across all published replies returned for that post, including replies beyond the initially visible three. Each native search field identifies its source post. It searches original body text/code and public author/affiliation fields with the existing Unicode-normalized AND-term matching. Anonymous private identity fields and unpublished drafts are excluded. Typing stays unapplied until submission; existing IME, Escape, pending-input and localization behavior is reused.

Results show original matching passages, matching counts and previous/next navigation. Full rich replies render only after an explicit expansion; the search path offers one full-body disclosure rather than stacking it with the normal preview disclosure. A local formatting fallback preserves original text and the composer. An always-present results region keeps native controls associated even with no matches; clearing the empty result returns to the existing search input.

Reading an out-of-filter author reply and returning restores the applied search, position and pending native input through the existing reading controller. Search changes do not publish or request more data. The composer and its draft/caret/two-scroll state remain independent. Hidden/inert/stale/account-checking guards retire new search, clear, match-navigation and disclosure actions. Applied search survives same-owner collapse/reopen; account changes retire the card and its local reading state.

The new StrictMode fixture covers18 replies with matches outside the first three, original code/math reading without eager formatting, public affiliation versus anonymous identity/private draft exclusion, full-width multi-term input, zero-match recovery, IME/Escape, locale identity, out-of-filter reading return, pending search selection/scroll, hidden/stale/account-loading guards, same-owner reopen and guest retirement without mutations. Existing card-action, sharing, editing, quoting, search and full-thread reading fixtures remain in the local checks. A separate guest loopback HTTP/SQLite flow searches both a community and interview card through real services and verifies unchanged database contents and API read counts. Physical browser geometry, native clipboard/IME and production/numerical execution are not claimed.
