# Saved-problem pagination and controls

The private saved-problem page uses the same native pagination controls as the paper/exercise library: 20, 50 or 100 results, a bounded numbered-page window, previous/next, direct page entry and a compact top pager. The page reports the current visible range and total. At narrow widths the numbered window yields to a current-page summary; native controls keep 44px targets. Search, status and bookmark controls share those target sizes and theme-aware focus/hover states.

`page` and `page_size` are optional bounded parameters of the root favorites URL. Defaults are omitted, queries and status remain validated, and named private study-list URLs retain their existing grammar. Explicit page/size changes push browser history; local search/status changes replace the current entry and reset to page one while retaining page size. Changing size keeps the first visible cohort. Search Escape clears only without modifiers, repetition or IME composition. Invalid jump input is announced locally; Escape restores the current page. A changing result count preserves an in-progress jump draft and validates against the new limit.

Private membership still uses one owner-scoped snapshot. Client pagination, search and browser history do not request another page or mutate account data. Reentering the private list revalidates membership once. Practice and sign-in links carry the full canonical page/search/status/size scope; the existing reading-return mechanism restores the originating row on the exact page and yields to newer user input.

Removed rows stay in place for undo during the current visit, with an explicit explanatory note. Refresh uses the latest successful authoritative snapshot to prune those rows; a failed refresh retains the existing view. If the saved count changes and the requested page no longer exists, its URL remains unchanged until the user chooses the first or last valid page. Search/status survive that recovery. Empty filtered views offer an explicit reset that focuses the persistent search input.

The optional pagination module loads independently from row bookmark controls. Loading or failure retains native previous/next controls; a local retry focuses the persistent list synchronously. Pagination rejects actions from hidden, stale-route, old-owner or unavailable-progress views. No deferred completion moves focus away from newer work.

Verification uses actual React/StrictMode and JSDOM, including 61 catalog problems, every row exactly once, page sizes, invalid/IME/fullwidth jumps, locale identity, native history, optional loading/failure/retry, membership undo and shrinking-page recovery, owner changes, unchanged private editor/draft/caret/scroll, and actual App practice-anchor traversal and row return. These checks do not establish physical browser geometry or native IME behavior.

A second disposable authenticated JudgeHandler/ProblemBookmarkService/SQLite check seeds 61 bookmarks and exercises the real private page over HTTP. Paging reuses one snapshot; reentry performs one revalidation. It compares the entire database projection before and after the UI flow and checks foreign keys. Runtime/numerical sources and release/deployment workflows are unchanged.
