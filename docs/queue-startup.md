# Deferred judge transport at startup

The initial library shell needs immediate submission error messages, but not the server job request, validation and polling implementation. These messages now live in a small pure module. App and the queue hook import it directly; the original judgeJobs exports remain compatible for existing callers. The actual request, cancellation, retry, receipt and result-validation code is unchanged. Build checks require the transport markers to remain available in deferred assets and absent from initial assets.

The queue client identifier is created or read only after the deferred controller is available and its owner/readiness lease is still valid. An ordinary library mount makes no queue identifier or session-storage write. Explicit submission and pending-receipt recovery use the existing client format and storage key. Pending recovery remains GET-only, and identifier/storage failures stay within the existing recoverable submission flow instead of running identifier creation during render.

An instrumented production build records the actual initial module graph and final emitted asset sizes using the same Node22 level9 gzip convention as check-build. Module renderedLength is an attribution before minification, not a download-size metric. These are byte and dependency measurements, not physical browser timing claims.

The new actual React StrictMode hook fixture instruments module evaluation while keeping the controller, admission, request, polling and parsing implementations real behind a controlled fetch boundary. It checks no-receipt startup, delayed-import owner retirement before client creation or POST, captured source/client/expected-user binding, existing-client GET-only resume and local identifier failure/retry. A separate failed-controller fixture retains pending receipts and immediate bilingual reload guidance without allocating a client or issuing a request. Existing queue/controller/data checks cover response validation, backoff, cancellation and uncertain-receipt recovery. No real judge job, numerical SDK, archive or production workload is executed.
