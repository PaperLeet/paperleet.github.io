# Curated practice ordering

Role-based curated lists offer Curriculum order, Easy first and Short time
first. The default remains the role curriculum. Equal or unknown metadata
preserves that curriculum order, with unknown values after known ones.
The source-neutral ordering helper also serves reported concepts without
manufacturing report rows, contributor counts or publication dates.

Curated and reported lists keep separate validated enum-only tab preferences.
A saved report-chronology choice does not become a curated choice; changing
curated practice does not overwrite report ordering. Source transitions retain
the appropriate preference. Curated lists keep their editorial labels and
expose no contributor or report-recency options. Metadata ordering uses
Practice order positions; default curriculum rows keep the editorial icon.

The native selector associates its current-source help and result region.
Existing role, search, difficulty, time and learning-state scope remains in
place. Default practice navigation captures an ordered six-row batch, while
an explicit practice group keeps its selected order. Sorting retains mounted
guides, hints and their scroll state, and retires an older pending source
return. Hidden, inert, retired and account-checking controls cannot update the
preference. Denied session storage has an in-memory fallback.

Actual React/JSDOM checks cover complete six/all row cohorts, stable curriculum
ties, missing and late metadata, both preferences and source transitions,
labels and native associations, scope intersections, practice queues,
explicit-group precedence, locale, retained reading state, storage denial,
inactive controls and newer-focus precedence. Public source data, practice
grades, private code, drafts, caret and both scroll axes remain unchanged;
the controlled fixture observes no API calls. These are source/DOM checks,
not physical browser geometry or native operating-system verification.
No schema, API, dependency, problem or numerical-runtime changes are added.
