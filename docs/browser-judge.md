These are bounded torch-like teaching adapters, **not the native PyTorch wheel or a general replacement for PyTorch**. Existing `import torch`, function signatures, maintained pytest files, reference implementations, mutants and experiment loops are retained. Test counts and precision tolerances are unchanged. Every browser run calibrates its runtime against the reference and every maintained mutant before executing the captured learner source. Unsupported APIs do not count as successful mutation detection. Ordinary assertion failures, syntax errors and unfinished TODOs are learner feedback and do not trigger an automatic server run.

## Differentiation and compatibility

`paperleet/browser/numpy_autograd.py` implements analytical vector-Jacobian products for the supported modules: batched/broadcast matmul, supported two-input einsum, elementwise arithmetic, stable softmax, masks/where, reductions, indexing (including repeated indices), reshape/transpose/permute, expansion and repeat. Leaf gradients accumulate through `backward`; `autograd.grad` returns derivatives without accumulating into leaves. `detach` and `no_grad` disconnect the relevant paths. LoRA uses genuine gradients and Adam moments/bias correction on the original 300-step loop. NumPy supplies CPU linear algebra, including the matrix-rank check.

The distillation lessons use bounded `nn.Linear`, positional `nn.Sequential`, SiLU and SGD, with the original model sizes, loops and thresholds. SGD supports momentum, dampening, weight decay, Nesterov and maximize; advanced execution options and closures require the server. Independent native tests compare identical-array outputs, input/weight/bias gradients and multiple optimizer updates. Deep-copied leaf parameters own separate storage/version counters, preserve shared module identity and can be frozen for EMA; copying recorded non-leaf graphs is unsupported. Named no-grad EMA updates preserve identity and invalidate saved aliases. `torch.testing.assert_close` retains native float32/float64 defaults and strict shape/dtype checks; no maintained assertions are rewritten.

Python scalar comparisons now retain a floating tensor’s precision, including strict float64 ratio endpoints. Adjacent representable values and explicit scalar-tensor promotion are checked against native PyTorch.

The independent parity tests compare the adapter and **native PyTorch on identical arrays** for values, batched/vector/broadcast matmul gradients, masked attention gradients, einsum, repeated indices, views, accumulation and Adam steps in float32/float64. CPU MT19937 integer sampling and float32/float64 uniform conversion are explicitly matched to native PyTorch and verified on 20,000 preference pairs. This keeps the unchanged DPO convergence threshold meaningful. Normal samples remain deterministic NumPy draws and are not bitwise identical to PyTorch; browser and native normal-data training curves need not match point for point. Both must meet unchanged experiment thresholds. Stable log-sigmoid/log-softmax, gather gradients, clamp/trigonometric derivatives, variance/std, pairwise distances and the separate LayerNorm oracle also have independent native checks.

The multi-head attention suite's library oracle uses raw NumPy SDPA and its own analytical VJP rather than the learner's Tensor softmax/matmul graph. Native parity covers boolean/additive masks, completely masked rows, broadcast batches, causal/non-square inputs, custom scales, empty query/key sequences, and additive-mask gradients in both precisions. Dropout, grouped-query attention and combined causal/mask options still require the server. Concatenation/stacking preserve gradients through duplicate and strided inputs; ReLU uses a zero derivative at zero. AdamW's separate stateful NumPy oracle exposes per-parameter steps and moments; differential tests cover learning-rate changes, decoupled decay, missing gradients and zeroing behavior. Advanced optimizer options and parameter groups remain unsupported.

RL bundles include the original `rl_envs.py`; Dr. GRPO also includes its unchanged GRPO solution/experiment dependencies. No environment, seed, rollout size, training loop, or acceptance threshold is replaced. Replacement multinomial sampling with more than one draw follows the production-pinned PyTorch 2.6 [CPU CDF algorithm](https://github.com/pytorch/pytorch/blob/v2.6.0/aten/src/ATen/native/cpu/MultinomialKernel.cpp); small integer permutations follow its [CPU shuffle](https://github.com/pytorch/pytorch/blob/v2.6.0/aten/src/ATen/native/TensorFactories.cpp). Independent tests compare exact draws and subsequent generator state across mixed categorical sampling, permutations and uniforms in both precisions. Single-draw multinomial uses independent exponential races for a faithful categorical distribution with either replacement flag; its seeded stream differs from native PyTorch. Multiple draws without replacement and permutations over one million items require the server. Normal draws retain the NumPy behavior described above.

Additional native parity covers zero-safe cumulative-product VJPs, split/repeat-interleave view gradients, elementwise minimum/maximum gradient sharing (including ties/NaNs), the PPO clipped objective and frozen targets, differentiable two-dimensional linear solves, and direct/nested module parameters. The bounded `nn.Module` interface supports direct `Parameter` attributes, nested modules, parameter iteration and forward calls; state dictionaries, hooks, other standard layers and unimplemented interfaces still require the server. Differentiable in-place writes explicitly fall back instead of silently dropping gradient paths.

Clamp uses subgradient 1 at the bounds, matching the hosted worker's pinned PyTorch 2.6 contract ([upstream implementation](https://github.com/pytorch/pytorch/blob/v2.6.0/torch/csrc/autograd/FunctionsManual.cpp)). The local installed PyTorch version chooses differently at these nondifferentiable kinks, so an explicit production-contract test covers the bounds and differential tests compare smooth points.

Higher-order derivatives, CUDA, custom extensions, unimplemented PyTorch modules/operators and in-place editing recorded by autograd are outside this backend. Known unsupported APIs raise `BrowserUnsupported`. Auto mode falls back to the native server queue, using the **same captured source** even if the user continues editing. Browser only reports incompatibility without submitting to the server. Server can always be selected explicitly. Other unvalidated modules remain on the server. The supported subset will not accept every valid PyTorch implementation; general PyTorch compatibility and cross-browser/mobile coverage remain beyond this prototype.

The contrastive-learning operators include Euclidean/Frobenius norms with zero-safe analytical VJPs, epsilon-clamped L2 normalization, stabilized log-sum-exp, vector/matrix diagonal extraction/construction, and differentiable `ij`/`xy` meshgrids (including scalar, empty and repeated inputs). Cross entropy uses an independent raw NumPy log-partition and analytical VJP, distinct from the Tensor log-sum-exp expression used by the CLIP tests. It supports finite `[N,C]` logits, int64 class-index `[N]` targets, ignored targets and all three reductions. Native parity includes extreme logits, ignored/empty batches, zero and sub-epsilon features, nonfinite/empty log-sum-exp reductions and diagonal offsets. Weighted/smoothed/probability-target cross entropy, other norm orders and `out` arguments remain unsupported. API semantics follow the official [normalization](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.normalize.html), [cross entropy](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.cross_entropy.html), [log-sum-exp](https://docs.pytorch.org/docs/2.14/generated/torch.logsumexp.html) and [meshgrid](https://docs.pytorch.org/docs/2.14/generated/torch.meshgrid.html) documentation within this bounded subset.

GLM-5 off-policy remains server-only. Its exact strict-boundary test exposed a NumPy/PyTorch exponential/logarithm rounding difference. The maintained boundary assertion is not relaxed and the module is not advertised as browser-compatible.

QLoRA adds dtype-inheriting, copying/detaching `new_tensor`, uint8 codes and int64 first-index argmin/argmax (including flattened `keepdim`). Flip, roll and triangular transforms have their own VJPs and copy their output storage. The Block Attention Residuals library oracle uses raw NumPy [RMSNorm](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.rms_norm.html) and separate analytical VJPs rather than calling the learner's RMS expression. Unweighted [covariance](https://docs.pytorch.org/docs/2.14/generated/torch.cov.html) has an independent NumPy value/gradient path; weighted or insufficient-observation cases fall back to the server.

The bounded `autograd.gradcheck` computes every first-order Jacobian entry analytically and by central finite differences, preserving caller input values and accumulated gradients. It supports real float64 tensor inputs/outputs, multiple inputs/outputs, default backward-check options, and at most 256 differentiable input entries and 256 output entries. It rejects overlapping storage and unsupported options. Bad analytical VJPs and detached value dependence fail the check; it never returns a placeholder success. This is numerical validation of the analytical training gradients, not a numerical-gradient training backend. Advanced/complex/large gradcheck workloads require the server.

Leaf parameter updates inside `no_grad` support `+=`, `-=`, `*=`, `/=` and indexed assignment while retaining the parameter object, `requires_grad`, accumulated gradients and storage aliases. Views, `detach`, and dtype-preserving casts share allocation version counters. Forward graphs save versions of operands, frozen constants, masks, indices and VJP output arrays; backward validates them before accumulating any gradients. Adam and AdamW updates also invalidate stale graphs. The weak-reference registry does not retain discarded arrays. Checks compare repeated updates, future gradients, aliases and stale-graph rejection against native PyTorch. This follows PyTorch's [no-grad optimizer and in-place correctness contracts](https://docs.pytorch.org/docs/stable/notes/autograd). The bounded adapter guards every operand conservatively: some valid native graph/view reuse patterns require the server. Non-leaf in-place updates and updates recorded by autograd remain unsupported.

REPA, I-JEPA and DistiLLM-2 retain their original projector, masked-prediction and dual-response optimization loops. Smooth L1 uses an independent raw NumPy value/analytical-gradient oracle for both inputs, including beta=0 and all reductions; MSE supports the I-JEPA wrong-objective mutant rather than treating an unsupported call as successful mutation detection. Stable `logaddexp` includes broadcast gradient reduction. Native parity covers both precisions, strided and empty inputs, piecewise boundaries, extreme logits and both input gradients. Mixed-dtype/broadcast loss targets and legacy loss options remain on the server.

Real float32/float64 [`SVD`](https://docs.pytorch.org/docs/stable/generated/torch.linalg.svd.html) supports batched square, tall and wide matrices, compact/full output shapes, singular values and analytical VJPs for all three outputs. Rectangular complement terms retain gradients outside the singular subspaces; arbitrary full-basis completion columns are ignored as in native PyTorch. Native checks align sign conventions in constant upstream weights and compare all three VJPs, while separate central differences validate the polar factor. Mutating any saved decomposition output invalidates its old graph. Rank-deficient/repeated or numerically unresolved singular-vector gradients, extreme squared-spectrum overflow/underflow, complex inputs, drivers and output buffers require the server. Forward rank-deficient/repeated-spectrum products remain available; no acceptance threshold is relaxed.

The maintained Muon tests retain an independent raw NumPy `eigh` Gram-matrix oracle and `qr` input-basis check. These two helpers support real forward/no-grad values; differentiable eigendecomposition/QR and other QR modes use the server. Tensor factories retain dtype/device without inheriting gradients, including when `dtype=None` is passed explicitly; `full_like` also retains the existing dense strided layout. Product VJPs handle zero factors analytically; `amax` shares gradients at ties; integer rounding preserves large integers exactly and floating rounding uses ties-to-even with zero gradients. Stable softplus, vector outer products and chunk views have native gradient/value checks. Nonfinite product gradients and decimal rounding require the server.

Muon Split remains the exact-polar teaching exercise, SVDQuant remains CPU fake quantization, FlashAttention remains a differentiable block-softmax numerical exercise, and KDA uses supplied projected tensors and a small recurrent memory example. Browser support preserves those existing scopes and experiments.

Bounded [`topk`](https://docs.pytorch.org/docs/stable/generated/torch.topk.html) supports largest/smallest selection, all axes, empty selections, scalar conventions and int64 indices. Its analytical gradient follows the returned indices; tied values need not select the same indices as native PyTorch, whose contract does not promise tie stability. Sorted output is also permitted when `sorted=False`. Functional [`scatter`](https://docs.pytorch.org/docs/stable/generated/torch.Tensor.scatter_.html) supports scalar writes (including duplicate destinations and boolean masks) and equal-shaped tensor sources with unique destinations. Independent native checks cover preserved-input/source gradients, shared inputs, partial rows, strides, empty selections and both precisions. Modified selection indices invalidate saved graphs. Tensor-source duplicate destinations, scatter reductions, scalar scatter and top-k output buffers require the server. `count_nonzero` produces int64 counts on wasm32 and supports dimension reductions. Python's integer-index protocol accepts only single-element integral/boolean tensors, retaining the original OPSD scalar-loop tests without rewriting them.

Stable [`argsort`](https://docs.pytorch.org/docs/2.14/generated/torch.argsort.html) preserves the order of tied keys in ascending and descending order, including unsigned values and signed integer extremes without overflow-prone negation. Indices remain int64 on wasm32. [`cartesian_prod`](https://docs.pytorch.org/docs/2.14/generated/torch.cartesian_prod.html) keeps lexicographic product order, the one-vector shape convention, empty products and analytical gradients to every input, including repeated inputs. [`Tensor.int`](https://docs.pytorch.org/docs/2.14/generated/torch.Tensor.int.html) converts to int32 and disconnects integer results from autograd. Independent native checks cover these semantics in both precisions, with strided/empty inputs and NaN sorting.

The world-model experiments retain their original teaching scope and data: LeWM jointly trains a scalar encoder and linear dynamics, CEM uses a supplied additive latent transition, and Causal-JEPA trains a small object-trajectory probe. Browser compatibility does not turn these into pixel training or full-paper benchmark reproductions. The original files, experiment loops, gradient tests and numerical thresholds are unchanged.

## Isolation and account progress

Shared `assert_close_located` failures carry optional bounded `comparison` metadata for shape or scalar-at-index differences. The assertion type and numerical tolerances remain unchanged. Both pytest collectors preserve it; the hosted validator and frontend sanitize known fields without using diagnostics to determine acceptance. Malformed optional metadata is dropped while the original failed row and trace remain available. The UI shows zero-based indices, exact round-trippable numbers, text-preserved large integers, explicit NaN/Infinity values and applicable tolerance bounds. Full tracebacks are expandable for structured failures; older/unstructured failures keep their error text visible.

The browser artifact serializer recursively converts nonfinite tensor/NumPy/Python values to readable strings before strict JSON encoding. A learner experiment producing NaN therefore remains a failed test with its actual artifacts, rather than becoming a runtime-loading error or a fabricated numeric chart. Coverage tests exercise the complete NaN-producing attention suite and strict JSON serialization.

Learner Python executes in a disposable classic Worker inside an opaque-origin `sandbox="allow-scripts"` iframe. It has no DOM or site storage access. The iframe CSP permits only self-hosted public runtime assets, excluding `/api` and third-party destinations. Messages are checked against the frame and a fresh nonce. Stopping, changing accounts, unmounting or exceeding the deadline removes the frame and worker. Phase limits are 90 seconds for initialization/calibration, 30 seconds for execution, and 120 seconds total; bundle downloads are bounded to 30 seconds. The UI remains responsive while Python or training runs.

Live progress starts before public test-bundle downloads and distinguishes Python initialization, package loading and test preparation. The Python pytest hook reports actual completed reference tests, checked mutants and completed learner tests through Pyodide's [JavaScript function proxy](https://pyodide.org/en/0.29.4/usage/type-conversions.html). The bilingual UI shows three steps, a count when known, and an indeterminate loading bar otherwise. Completed tests are not presented as passed tests; only the final parsed report determines feedback. Repeated progress messages cannot renew the phase or hard deadline, change acceptance or include learner output. The parent validates expected totals, monotonic phases/substeps/counts and the existing nonce/source before displaying updates. Nonurgent progress rendering preserves editor responsiveness; stale runs and account changes cannot overwrite the active run's state. Stop remains available throughout loading and execution. Older immutable harnesses without callback parameters use phase-only progress and still run their complete suites.

Hosted browser results are local feedback, held in memory and discarded on account changes/refresh. They never update authoritative account progress, shared statistics or rankings. Signed-in users can select **Verify on server**; that server executes and records its own result. Local development can retain browser completions locally. Existing server authentication, private draft synchronization, draft conflicts and durable queue recovery remain in force.

## Runtime assets and deployment

Reports retain the submitted source's SHA-256 through parsing and draft/history storage. The test panel and submitted-run experiments compare it with the editor's exact UTF-8 contents. Editing marks the previous results as belonging to an earlier submission; restoring the exact source restores the match. Asynchronous checks discard superseded work. Legacy reports and environments without Web Crypto show an unconfirmed version and invite a rerun. Historical completion remains intact, while next-step recommendations require results matching the current code.

`npm run dev` and `npm run build` run `scripts/prepare-browser-runtime.mjs` first. It copies Pyodide **0.29.4** from the exact npm dependency and downloads NumPy **2.2.5**, pytest **8.3.5** and dependencies using the official Pyodide lockfile SHA-256 digests. Cached wheels are verified and reused; initial preparation requires network access. Build failures are explicit. No GPU runtime is downloaded or required.

The runtime is self-hosted in `web/public/browser-runtime/` (ignored by Git), loaded only when a browser run is requested. The homepage does not preload Python/NumPy. Versioned runtime assets are immutable; worker scripts revalidate. `paperleet export` emits content-addressed compatibility bundles from the maintained Python files. Re-export after changing adapters, the harness, tests or reference solutions. Vite dev/preview and Caddy provide CORS only on the public runtime/worker asset paths so the opaque sandbox can load them.

Version 2 problem manifests contain the unchanged tests, reference, mutants and experiment dependencies, plus a `runtime_bundle_url`. Adapter code, the harness and four shared package files are stored once per backend in `data/browser-judge/runtime-HASH.json`. The loader accepts only fixed content-addressed asset paths, validates problem/backend identity and rejects shared-file overrides before assembling an independent bundle for the sandbox. Existing self-contained version 1 bundles remain supported; retain previous hashes for cached clients. Caddy gives all `data/browser-judge/` hashes immutable cache headers.

The first module still downloads its backend's shared pack and the Python runtime; this change primarily saves repeated code downloads when switching between modules. Later modules using the same backend fetch only their own tests and problem data.

Across the current 41 modules, active exported assets total **771,767 bytes**, compared with **4,716,257 bytes** for equivalent self-contained bundles (83.6% less). The earlier 22-module baseline measured 422,426 bytes versus 1,884,763 bytes (77.6% less), or 97,452 versus 461,942 bytes when each asset was gzip-compressed. These measurements exclude Pyodide/wheels and retained historical hashes. The browser keeps a bounded four-entry cache of public runtime packs and coalesces concurrent downloads. Failed downloads can retry; stopping a caller promptly abandons its run without cancelling another caller's shared download. Public downloads remain bounded to 30 seconds. No learner source, reports, calibration outcomes, or Python worker state are cached: every run still starts an isolated worker and checks the reference and every mutant.

Upstream projects and license information: [Pyodide](https://github.com/pyodide/pyodide), [NumPy](https://github.com/numpy/numpy), [pytest](https://github.com/pytest-dev/pytest). Archives retain upstream license metadata. The bounded autodiff adapter is implemented in this repository; it does not depend on a third-party PyTorch port.

Loading, conflicts, stale draft snapshots and owner changes prevent overwrite; logout/account switching clears the claimed handoff.
